# Parallel implementation contracts

Preserve the Oxygen React UI, both themes, breadcrumbs and contextual sidebars. Reuse SolidCraft's native document/commands and existing tested third-party engines. Implement measured workflows; command names, placeholders and mocks do not count as completed features.

The shared Project envelope gains `native_document: dict | None` and `domains: dict[str, dict]`, both defaulting safely for existing v1 projects. The native document is the canonical SolidCraft design including its format version and stable IDs. Host domains hold versioned engineering/process/electrical/review metadata, not a second CAD model. The core owner implements native document persistence/migration, replay, multibody/surface representation and native transaction routes. Native edits use expected revision, actor, command, params through Store. Parent integrates central API/jobs/CLI and React shell.

Native API contract: `POST /api/native/execute` with `{expected_revision, actor, command, params}` returns `{project,result}`; `GET /api/native/inspect` returns a native summary and command enablement. Native transactions persist the native document and use existing Store revision/undo/redo/invalidation. Native import routes resolve immutable project assets and never grant arbitrary project-controlled filesystem execution.

Domain IDs: modeling, assemblies, drawings, manufacturing, simulation, electronics, visualization, interop, platform. A domain may supply `src/o3d/domains/<id>.py` exporting lightweight `validate(data)->dict`, `execute(store, project, operation, payload, cancel=None)->dict`, and optionally `mount(app,store,jobs)`. Imports must not install tools, run external processes or load large CAD libraries. Output artifacts stay inside Store cache. External workers are explicit, cancellable and report real failures; missing engines never report success. Parent wires generic domain save/run routes and asynchronous jobs. Each domain payload uses its own `schema_version: 1` and module-owned Pydantic schema.

Frontend domain panels export `default function <Domain>Panel(props: DomainPanelProps)` from `frontend/src/workspaces/<domain>/Panel.tsx`. Use the shared contracts file and existing components/ui. Parent mounts panels in the existing project/workspace menu and passes revision-safe callbacks. Agents do not modify App.tsx, api.ts, generated.ts or central style.css unless explicitly assigned. Domain-local styles may use existing semantic CSS variables. No permanent empty panels or unrelated redesign.

Each owner updates `docs/parity/<domain>.json` with row IDs from the audited register, actual implementation paths, executed tests and honest remaining work. The public implementation notes must be original code/documentation; do not copy private wiki/research/customer sources into this repository.

Use isolated disposable projects. Original checkout preview at localhost8787 belongs to the user. Python in worktrees must use PYTHONPATH=<worktree>/src because the shared venv editable install points at the original checkout. Set O3D_ENGINE_BINARY to the baseline built engine until the core owner supplies its new binary/protocol. Native mesher/solver environments may be shared read-only. Own files only; commit on the assigned local branch and report the exact commit. No force pushes, vendored source rewrites or upstream PRs. Parent handles public integration/push/CI.
