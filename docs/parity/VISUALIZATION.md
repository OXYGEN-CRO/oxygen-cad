# Product scenes and presentation

Visualization uses `Project.domains.visualization`, schema version 1. `validate` admits bounded typed settings. Generic Store domain saves provide revision checks and undo; render operations take a captured Project and never change its physical materials, CAD geometry or engineering placements. The renderer reads canonical native scene meshes through `opened_native` / `oxygen.scene`. Existing source-feature projects use the core's migration reader; no alternate geometry is substituted when the native engine fails.

`scene`, `capabilities`, `gallery`, `import_image`, `sample`, `render` and `publish` are the domain operations. Image imports accept base64 bytes with a six-MiB upload ceiling, normalize to bounded PNG, store them by SHA-256 in the project, and verify their hash on use. Render outputs live in Store cache and use the existing artifact endpoint. Missing targets and missing/tampered assets fail explicitly. A render manifest records source revision, full document digest, exact scene, scene digest, renderer, algorithm and limitations. Gallery results remain available after reopening and display stale revision labels.

The CPU raster renderer uses triangle clipping, a per-pixel z-buffer, perspective-correct barycentric interpolation, direct diffuse/Blinn-Phong illumination and sorted alpha compositing. It supports image decals/textures in world millimeters before presentation translations, including cylindrical Z mapping. It does not simulate shadows, refraction, reflections, HDR or global illumination, and is not described as photorealistic. Sections produce clipped surfaces without solid caps. Intersecting transparent surfaces use an approximation. Maximum output is two megapixels; triangle, raster-work and animation-pixel budgets refuse oversized requests.

The native CPU-raytrace path invokes the shipped backend through preflight/start/status/export. It refuses host scene features it cannot faithfully lower. The UI offers it only when the actual native inventory advertises its executor. Saved samples/seed control real native progressive sampling; deterministic rerenders are checked byte for byte. The optional finite native ground stage uses explicit clearance, margin and linear RGB reflectance without creating CAD bodies. A decoded pixel comparison checks actual shadow enable/disable. Ground and shadows appear in the native output; the interactive viewport previews direct lighting. CPU raytrace is a preview, not evidence of general photorealistic parity.

Storyboards contain absolute camera, translation and visibility snapshots plus callout text. Camera and translation interpolate; visibility and callouts step at their keyframe. Sampling is pure and does not accumulate transforms. GIF output requires a frame rate dividing 100 so its centisecond timing is exact. PNG sequence ZIPs include timing metadata. MP4 is conditional on an installed ffmpeg encoder and reports encoder failures. Frames include both endpoint poses; playback duration remains the encoded frame count divided by FPS. No cloud rendering or hosted sharing is offered.

`Viewport` accepts an optional canonical `nativeScene` prop and supports the visualization event bridge without changing selection, original context references or stress/displacement field rendering. The domain panel preserves the application's controls and theme tokens. `docs/parity/visualization.json` distinguishes implemented paths, executed evidence and remaining acceptance for each audited row.

The integrated browser test uses `tests/fixtures/visualization_server.py`, which creates a disposable source project and refuses the user's preview port. Build the integrated frontend, start that fixture with `PYTHONPATH=src O3D_TEST_PORT=8954`, then run `O3D_BROWSER_URL=http://127.0.0.1:8954 O3D_VISUALIZATION_INTEGRATION=1 npx playwright test tests/visualization-integration.spec.ts` from `frontend/`. Set `O3D_ENGINE_BINARY` to the CPU-host-enabled release engine. The test verifies the fixture's exact name before writing. An isolated development server may instead proxy the fixture API, with HMR disabled so concurrent source work cannot remount an edited form.

Executed integrated checks cover scene save, draft preservation during polling, native progressive rendering through the job service, retained image/gallery reload, undo/redo and storyboard ZIP download. Job tests cancel a running publication and change real extrusion geometry during a separate captured native render. The stale output retains its original revision and is byte-identical to a seeded render of the original snapshot; the current project retains its newer geometry.
