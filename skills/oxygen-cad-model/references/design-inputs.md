# Design inputs

Prefer dimensions, constraints, interfaces and measured source data over a visual guess. On image/drawing tasks record the known scale, views/projection, datums, specified versus assumed dimensions, and unknown hidden features. A rendering does not establish alloy, wall thickness, tolerance or load.

Keep a short task-specific ledger only where ambiguity affects the result: intended function, mounting interfaces, units/datum, important clearances/locked dimensions, available material/process constraints and missing inputs. Preserve existing project conventions rather than replacing them with a generic template. An inspection/export request need not become a full design interview.

Use the parts-search skill when an actual bought component can supply geometry; distinguish its verified interfaces from a placeholder envelope. Record the source and actual imported orientation/scale. Typed native modelling commands do not yet make supplier references into moving assembly mates.

Choose a supported project feature for editability and numeric verification. For additional native operations inspect actual command metadata/schema and allowlisting. Unsupported physics, feature history or animation are gaps, not instructions to insert arbitrary executable code or silently select a different kernel.
